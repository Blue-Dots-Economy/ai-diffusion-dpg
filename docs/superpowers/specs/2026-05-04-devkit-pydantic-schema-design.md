# DPG Config Schema System — Design

**Date:** 2026-05-04
**Status:** Draft for review
**Goal:** Eliminate config validation and runtime errors in devkit-generated configs by introducing comprehensive Pydantic schemas that the LLM uses at generation time and the deploy wizard uses at framework-edit time.

---

## 1. Problem Statement

Configs generated by the devkit agent currently fail at two points:

1. **Schema validation failures (deploy time)** — values like `max_tool_rounds: 0`, key names like `vector_store`, and section paths like `observability.domain` (which double-nests) pass through the devkit's tool handler silently, then fail when the runtime block parses the merged YAML.
2. **Runtime crashes (post-deploy)** — values that pass devkit's thin `validate_partial()` but violate runtime invariants (e.g., `queue_backend: memory` instead of `log/redis/webhook`) crash the block at startup.

Two underlying causes:

- **Devkit prompts inject blank YAML templates as field-name guides.** The LLM sees `max_tool_rounds: 3` in the template but no constraint that it must be ≥ 1. It writes `0` for an agent with no external tools and the agent_core crashes.
- **Devkit validation is partial and runs at render time.** By the time `validate_partial()` fires, the LLM has already moved on through several phases. The error is hard to recover from.

A third gap exists in the deploy wizard: the **DPG Framework Values** step (`PUT /api/projects/{slug}/deploy/dpg-values/{block}`) only validates that the operator-edited content is parseable YAML — it does **not** validate the values against any schema. Operators can submit `port: -1` or `sample_rate: 5.0` and the file is written without complaint.

---

## 2. Solution Overview

Introduce **two parallel sets of Pydantic schemas** in `dev-kit/dev_kit/schemas/`:

| Set | Purpose | Audience | Where used |
|---|---|---|---|
| **Domain schemas** | Validate domain-configurable fields the LLM writes via `update_config` | LLM (passed as Pydantic source code in phase prompts) | `accumulator.update()` validation hook + phase prompts |
| **DPG schemas** | Validate framework infrastructure fields the operator edits in the deploy wizard | Operator (via deploy wizard UI) | `update_dpg_value` API endpoint validation |

The runtime schemas (`agent_core/src/schema/config.py` etc.) stay untouched. They are the authoritative source the new devkit schemas mirror — but the devkit schemas are owned by the devkit and are **not** imported from block packages.

### 3.2 Section-Split Domain Schemas — Rationale

> ⚠️ **Important design choice — read this before reviewing any schema below.**
>
> Domain schemas are **split per top-level config section**, not as a single per-block model. Each section gets its own Pydantic class (e.g., `AgentSection`, `PreprocessingSection`, `AgentWorkflowSection` — all three live inside `domain/agent_core.py`).
>
> **Why split:** Config is built incrementally across 12 phases. A required field like `agent_workflow.workflow_id` (set in phase 9) does not exist when phase 3 (language) runs. A single whole-block model would require **every** field to be `Optional` to avoid false-positive "missing field" errors during early phases — losing required-field enforcement entirely.
>
> Section-split models enforce required fields **within the section** at the moment the LLM writes that section. Phase 3 enforces `agent.primary_model` and `agent.fallback_model`. Phase 9 enforces `agent_workflow.workflow_id` and `agent_workflow.agent_system_prompt`. Each phase gets precise feedback about *its* missing fields, with no cross-phase noise.
>
> **What this means for validation:** When `update_config(section="agent", values={...})` is called, the accumulator merges the new values into its `agent` sub-dict and validates the merged dict against `AgentSection`. Constraints fire immediately; required-field errors fire only after merge.

### 3.3 Two Layers of Defence

**Layer 1 — Schema in the prompt (primary).** The phase prompt includes the relevant section class(es) as Pydantic source code. The LLM sees `max_tool_rounds: int = Field(ge=1, le=20)` directly in its context and generates conformant tool calls from the start.

**Layer 2 — Validation in the tool handler (safety net).** `accumulator.update()` validates the merged section against the schema. If invalid, the tool returns an error string the LLM corrects in the same turn.

## 4. Retry & Fallback Strategy

### 4.1 The problem

If validation in the tool handler keeps failing, the conversation can loop indefinitely:
```
LLM calls update_config → ERROR → LLM retries with same wrong value → ERROR → ... infinite
```

### 4.2 Retry counter design

A per-(block, section) attempt counter lives on the `ConfigAccumulator` instance (one accumulator per project conversation):

```python
import os

class ConfigAccumulator:
    _validation_attempts: dict[tuple[str, str], int]   # (block, section) → attempt count
    _MAX_VALIDATION_ATTEMPTS: int = int(os.environ.get("DEVKIT_VALIDATION_MAX_ATTEMPTS", "3"))
```

The cap is configurable via the `DEVKIT_VALIDATION_MAX_ATTEMPTS` environment variable
(default `3`). Lower values fail-fast to user fallback in production; higher values
give the LLM more room to self-correct in development.

**Counter lifecycle:**

| Event | Effect on counter |
|---|---|
| New user message arrives | Reset all counters to 0 |
| `update_config(block, section, values)` validates **OK** | Reset `(block, section)` counter to 0 |
| `update_config(block, section, values)` validates **FAIL**, attempt < 3 | Increment counter, return error to LLM, keep going |
| `update_config(block, section, values)` validates **FAIL**, attempt == 3 | Return **terminal** error to LLM, mark section as `STALE`, do **not** increment further |

**Why reset on new user message:** Each user turn is a fresh attempt. The operator may provide new information that changes the right answer — e.g., "actually, set `retry_attempts` to 4 with a longer backoff" — so prior-turn failures on different values shouldn't disable retries on values the LLM is now correctly attempting.

**Why per-(block, section):** A failure on `agent_core.agent` shouldn't disable retries on `agent_core.preprocessing.nlu_processor`. They're independent.

### 4.3 Fallback behaviour

When the LLM hits the 3-retry cap on a section:

1. The accumulator marks that section's status as `STALE` with the last validation error.
2. The tool returns to the LLM:
   ```
   VALIDATION_FAILED_AFTER_3_ATTEMPTS: <last error>.
   Tell the user we couldn't auto-configure this section and ask
   for guidance, OR call set_phase to move on and fix in Review phase.
   ```
3. The LLM is instructed (in `prompts/base.py`) to surface this to the user in plain language:
   > "I tried 3 times to set the agent's retry policy but the values aren't fitting. The model wants `retry_attempts: 5` but only 0–5 are allowed. Could you confirm what value should we use, or should we move on and fix this later in the Review phase?"
4. The Review phase (already exists) can re-attempt validation once the user provides a value.

### 4.4 Edge cases handled

- **Same wrong value retried:** Counter increments. Hits cap, falls back. No loop.
- **LLM calls a different section after failure:** Other section's counter is independent. Works normally.
- **Cross-field validator failure:** Same retry path. The error message includes which fields conflict (e.g., "primary_model and fallback_model must differ").
- **Schema-shape error (extra=forbid):** Same retry path. Error message lists the unknown key.
- **User correction mid-conversation:** The new user message resets counters. Retries available again.

### 4.5 Why a counter, not a different model

We deliberately do **not** escalate to a more capable LLM after retries — the conversation engine already runs Claude Sonnet (`DEVKIT_MODEL`). If Sonnet can't satisfy a constraint after 3 tries, the constraint is genuinely ambiguous (rare) or the model needs human guidance (common). Either way, asking the user is correct.

## 5. Phase → Section Mapping

This determines which section schemas are injected into which phase's system prompt.

| Phase | Block | Sections injected | Required fields enforced in section |
|---|---|---|---|
| `tier` | — | (no schema; classification only) | — |
| `overview` | — | (no schema; meta only) | — |
| `language` | agent_core | `AgentSection`, `PreprocessingSection`, `ConversationSection`, `ChannelsSection`, `HitlSection` | primary/fallback model, default_language, NLU model, blocked/escalation messages |
| `knowledge` | knowledge_engine | `KnowledgeSection` | collection_name (if enabled) |
| `knowledge` | agent_core | `ConnectorsSection` (internal) | knowledge_retrieval connector if KB enabled |
| `memory` | memory_layer | `StateSection`, `UserDataPersistenceSection`, `ReengagementSection` | session.ttl_minutes, persistent.graph.user_node |
| `user_state` | agent_core | `ConversationSection.user_state_model` | states list, default_state (Conversational only) |
| `trust` | trust_layer | `TrustSection`, `DignityCheckSection` | input_rules.blocked_phrases, hitl.queue_backend; dignity questions for Conversational |
| `tools` | action_gateway | `ToolsSection` (list, can be empty) | per-tool: id, type, category |
| `tools` | agent_core | `ConnectorsSection` | per-connector: name, invocation_rules.{call_when, on_empty, on_failure} |
| `workflow` | agent_core | `AgentWorkflowSection` | workflow_id, version, agent_system_prompt, default_fallback_subagent_id |
| `observability` | observability_layer | `OutcomesSection` | lifecycle (≥1 entry), metrics |
| `reach` | reach_layer | `WebChannelSection` (always), `VoiceChannelSection` (if voice selected) | web.ui.app_name; voice.raya.{voice_id, stt_language, tts_language} |
| `review` | All | (full validation pass; no new schema) | All previously-required fields |

### 6.2 `dev-kit/dev_kit/schemas/domain/agent_core.py`

```python
"""
Domain schemas for agent_core block.

Each class corresponds to a top-level section the LLM writes via update_config.
Phase prompts inject the relevant subset (see phase→section mapping in design doc).
"""
from __future__ import annotations
from typing import Optional, Any
from pydantic import BaseModel, ConfigDict, Field, model_validator

from dev_kit.schemas.enums import ClaudeModel, LanguageCode


# -- agent_core.agent (language phase) ---------------------------------------

class AgentSection(BaseModel):
    """LLM model selection + retry/timeout policy. Required: primary_model, fallback_model."""
    model_config = ConfigDict(extra="forbid")

    primary_model: ClaudeModel = Field(..., description="Primary LLM")
    fallback_model: ClaudeModel = Field(..., description="Fallback LLM (must differ from primary)")
    timeout_ms: int = Field(default=10000, gt=0, le=60000)
    retry_attempts: int = Field(default=2, ge=0, le=5)
    retry_backoff_seconds: list[float] = Field(default_factory=lambda: [0, 0.5, 1.0])
    max_tool_rounds: int = Field(default=3, ge=1, le=20)
    ask_for_consent: bool = False
    consent_prompt: str = ""

    @model_validator(mode="after")
    def primary_fallback_must_differ(self) -> "AgentSection":
        if self.primary_model == self.fallback_model:
            raise ValueError(
                "primary_model and fallback_model must be different — fallback exists "
                "to handle primary failures, using the same model defeats the purpose"
            )
        return self


# -- agent_core.preprocessing (language phase) -------------------------------

class LanguageNormalisationSection(BaseModel):
    model_config = ConfigDict(extra="forbid")
    model: str = Field(..., min_length=1)
    default_language: LanguageCode
    supported_languages: list[LanguageCode] = Field(..., min_length=1)
    min_detection_tokens: int = Field(default=3, gt=0)
    transliteration: bool = True
    code_switching: bool = True


class NLUProcessorSection(BaseModel):
    model_config = ConfigDict(extra="forbid")
    model: ClaudeModel
    confidence_threshold: float = Field(default=0.5, ge=0.0, le=1.0)
    user_state_confidence_threshold: float = Field(default=0.4, ge=0.0, le=1.0)
    domain_instruction: str = ""
    intents: list[str] = Field(default_factory=list)
    entities: list[str] = Field(default_factory=list)
    sentiment_classes: list[str] = Field(
        default_factory=lambda: ["neutral", "positive", "distressed", "frustrated"]
    )
    signal_intents: dict[str, str] = Field(default_factory=dict)


class PreprocessingSection(BaseModel):
    model_config = ConfigDict(extra="forbid")
    language_normalisation: LanguageNormalisationSection
    nlu_processor: NLUProcessorSection


# -- agent_core.conversation (language, trust, memory phases) ----------------

class UserStateDefinition(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: str = Field(..., min_length=1)
    signals: list[str] = Field(default_factory=list)
    guidance: str = ""


class UserStateModel(BaseModel):
    model_config = ConfigDict(extra="forbid")
    enabled: bool = False
    default_state: str = ""
    states: list[UserStateDefinition] = Field(default_factory=list)

    @model_validator(mode="after")
    def default_must_be_in_states(self) -> "UserStateModel":
        if self.enabled:
            ids = {s.id for s in self.states}
            if not self.default_state or self.default_state not in ids:
                raise ValueError(
                    f"default_state '{self.default_state}' must be one of declared states: {sorted(ids)}"
                )
        return self


class ConversationSection(BaseModel):
    """All conversation-level messages + optional user_state_model."""
    model_config = ConfigDict(extra="forbid")
    blocked_message: str = Field(..., min_length=1)
    escalation_message: str = Field(..., min_length=1)
    output_blocked_message: str = Field(..., min_length=1)
    unknown_intent_message: str = ""
    termination_message: str = ""
    consent_message: str = ""
    consent_decline_ack: str = ""
    profile_complete_message: str = ""
    returning_user_greeting: str = ""
    unsupported_language_message: str = ""
    user_state_model: Optional[UserStateModel] = None


# -- agent_core.channels (language, reach phases) ----------------------------

class TtsRulesConfig(BaseModel):
    model_config = ConfigDict(extra="forbid")
    numbers: str = ""
    money: str = ""
    dates: str = ""
    time: str = ""
    phone: str = ""
    abbreviations: str = ""
    output_script: str = ""
    english_loanwords: str = ""


class TurnAssemblerConfig(BaseModel):
    model_config = ConfigDict(extra="forbid")
    semantic_gate: dict = Field(default_factory=lambda: {"enabled": False, "confidence_threshold": 0.75})
    silence_trigger: dict = Field(default_factory=lambda: {"silence_ms": 0})
    max_wait_ceiling: dict = Field(default_factory=lambda: {"max_wait_ms": 0})

    model_config = ConfigDict(extra="forbid")
    system_prompt_suffix: str = ""
    tts_rules: Optional[TtsRulesConfig] = None
    turn_assembler: Optional[TurnAssemblerConfig] = None
    terminal_word: Optional[str] = None

    model_config = ConfigDict(extra="forbid")
    web: Optional[ChannelEntry] = None
    voice: Optional[ChannelEntry] = None
    cli: Optional[ChannelEntry] = None


# -- agent_core.connectors (knowledge, tools phases) -------------------------

class InvocationRules(BaseModel):
    model_config = ConfigDict(extra="forbid")
    call_when: str = Field(..., min_length=1)
    required_before_calling: list[str] = Field(default_factory=list)
    must_not_substitute: str = Field(..., min_length=1)
    on_empty: str = Field(..., min_length=1)
    on_failure: str = Field(..., min_length=1)
    bridge_line: str = ""


class ConnectorDef(BaseModel):
    model_config = ConfigDict(extra="forbid")
    name: str = Field(..., min_length=1)
    description: str = Field(..., min_length=1)
    input_schema: dict[str, Any] = Field(default_factory=dict)
    invocation_rules: InvocationRules


class InternalConnectorDef(ConnectorDef):
    """Routes to an internal block (e.g. knowledge_retrieval → knowledge_engine)."""
    route: str = Field(..., min_length=1)


class ConnectorsSection(BaseModel):
    model_config = ConfigDict(extra="forbid")
    internal: list[InternalConnectorDef] = Field(default_factory=list)
    read: list[ConnectorDef] = Field(default_factory=list)
    write: list[ConnectorDef] = Field(default_factory=list)
    identity: list[ConnectorDef] = Field(default_factory=list)


# -- agent_core.agent_workflow (workflow phase) ------------------------------

class RoutingRule(BaseModel):
    model_config = ConfigDict(extra="forbid")
    intent: str = Field(..., min_length=1)
    next_subagent_id: str = Field(..., min_length=1)
    conditions: list[dict] = Field(default_factory=list)
    session_writes: dict[str, Any] = Field(default_factory=dict)


class SubAgent(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: str = Field(..., min_length=1)
    name: str = Field(..., min_length=1)
    description: str = ""
    is_start: bool = False
    is_terminal: bool = False
    special_handler: Optional[str] = None
    valid_intents: list[str] = Field(default_factory=list)
    tools: list[str] = Field(default_factory=list)
    system_prompt: str = Field(..., min_length=1)
    opening_phrase: str = ""
    routing: list[RoutingRule] = Field(default_factory=list)

    @model_validator(mode="after")
    def non_terminal_needs_opening_phrase(self) -> "SubAgent":
        if not self.is_terminal and not self.opening_phrase.strip():
            raise ValueError(f"Non-terminal subagent '{self.id}' must have non-empty opening_phrase")
        return self


class AgentWorkflowSection(BaseModel):
    model_config = ConfigDict(extra="forbid")
    workflow_id: str = Field(..., pattern=r"^[a-z][a-z0-9_]+$")
    version: str = Field(..., pattern=r"^\d+\.\d+\.\d+$")
    agent_system_prompt: str = Field(..., min_length=20)
    subagents: list[SubAgent] = Field(..., min_length=1)
    global_intents: list[str] = Field(default_factory=list)
    global_tools: list[str] = Field(default_factory=list)
    global_routing: list[RoutingRule] = Field(default_factory=list)
    default_fallback_subagent_id: str = Field(..., min_length=1)

    @model_validator(mode="after")
    def fallback_must_be_declared(self) -> "AgentWorkflowSection":
        ids = {s.id for s in self.subagents}
        if self.default_fallback_subagent_id not in ids:
            raise ValueError(
                f"default_fallback_subagent_id '{self.default_fallback_subagent_id}' "
                f"is not a declared subagent id. Declared: {sorted(ids)}"
            )
        return self

    @model_validator(mode="after")
    def routing_targets_must_be_declared(self) -> "AgentWorkflowSection":
        ids = {s.id for s in self.subagents}
        for sa in self.subagents:
            for rule in sa.routing:
                if rule.next_subagent_id not in ids:
                    raise ValueError(
                        f"Subagent '{sa.id}' routing intent '{rule.intent}' targets "
                        f"unknown subagent '{rule.next_subagent_id}'. Declared: {sorted(ids)}"
                    )
        for rule in self.global_routing:
            if rule.next_subagent_id not in ids:
                raise ValueError(
                    f"global_routing intent '{rule.intent}' targets unknown subagent "
                    f"'{rule.next_subagent_id}'"
                )
        return self

    @model_validator(mode="after")
    def global_intents_must_not_overlap_subagent_intents(self) -> "AgentWorkflowSection":
        global_set = set(self.global_intents)
        for sa in self.subagents:
            overlap = global_set & set(sa.valid_intents)
            if overlap:
                raise ValueError(
                    f"Intents {sorted(overlap)} appear in both global_intents and "
                    f"subagent '{sa.id}' valid_intents — runtime crashes on overlap"
                )
        return self

    @model_validator(mode="after")
    def exactly_one_start_subagent(self) -> "AgentWorkflowSection":
        starts = [s for s in self.subagents if s.is_start]
        if len(starts) != 1:
            raise ValueError(
                f"Exactly one subagent must have is_start=true (got {len(starts)})"
            )
        return self

```

```python
def validate_domain_section(block: str, section: str, merged_data: dict) -> Optional[str]:
    """Validate one domain section. Return None if OK, error string if invalid."""
    top_level = section.split(".", 1)[0]
    schema = DOMAIN_SECTION_SCHEMAS.get((block, top_level))
    if schema is None:
        return f"Unknown section '{section}' for block '{block}'"
    try:
        schema.model_validate(merged_data)
        return None
    except ValidationError as e:
        return _format_pydantic_error(e)


def validate_dpg_block(block: str, parsed_yaml: dict) -> Optional[str]:
    """Validate a full DPG framework YAML against its schema. Return None or error."""
    schema = DPG_BLOCK_SCHEMAS.get(block)
    if schema is None:
        return f"Unknown block '{block}'"
    try:
        schema.model_validate(parsed_yaml)
        return None
    except ValidationError as e:
        return _format_pydantic_error(e)


def _format_pydantic_error(err: ValidationError) -> str:
    """Render a ValidationError as a single human-readable string for LLM/operator feedback.

    Includes the error type code, field path, message, and the offending input value
    so the LLM can self-correct on retry without resending the same wrong value.
    """
    lines = []
    for e in err.errors():
        path = ".".join(str(p) for p in e["loc"]) or "<root>"
        err_type = e.get("type", "unknown")
        msg = e.get("msg", "")
        # Include the offending value when present and small enough to be useful.
        # `input` is the raw value Pydantic rejected.
        offending = e.get("input")
        if offending is None:
            value_hint = ""
        else:
            try:
                rendered = repr(offending)
                if len(rendered) > 200:
                    rendered = rendered[:200] + "...<truncated>"
                value_hint = f" (you sent: {rendered})"
            except Exception:
                value_hint = ""
        lines.append(f"- {path} [{err_type}]: {msg}{value_hint}")
    return "\n".join(lines)
```

**Example LLM-facing error string** produced by this formatter:

```
VALIDATION_ERROR (attempt 1/3):
- agent.max_tool_rounds [greater_than_equal]: Input should be greater than or equal to 1 (you sent: 0)
- agent [value_error]: primary_model and fallback_model must be different (you sent: {'primary_model': 'claude-sonnet-4-6', 'fallback_model': 'claude-sonnet-4-6', ...})
- agent.foo [extra_forbidden]: Extra inputs are not permitted (you sent: 'bar')
```

The three pieces — error type code in brackets, the human message, and the offending value — give the LLM enough context to:
- Categorise the failure (constraint violation vs typo vs cross-field rule)
- See the exact value that was rejected (avoids retrying with the same wrong value due to merge confusion)
- Recover without needing the user to clarify intent

### 8.2 `accumulator.update()` changes

```python
def update(self, block: str, section: str, values: dict) -> str:
    """Merge values into block.section; validate; return 'OK' or error string."""
    if block not in BLOCKS:
        raise ValueError(f"Unknown block '{block}'")

    # Existing deep-merge logic (unchanged)
    self._merge_section(block, section, values)

    # New: validate the merged TOP-LEVEL section against its schema
    top_level = section.split(".", 1)[0]
    merged_top = self._data[block].get(top_level, {})
    error = validate_domain_section(block, section, merged_top)

    key = (block, top_level)
    if error:
        attempt = self._validation_attempts.get(key, 0) + 1
        if attempt >= self._MAX_VALIDATION_ATTEMPTS:
            # Cap reached — mark stale, return terminal error
            self.set_status(block, ConfigStatus.STALE)
            self._validation_attempts[key] = attempt  # do not increment further on subsequent calls
            return (
                f"VALIDATION_FAILED_AFTER_{self._MAX_VALIDATION_ATTEMPTS}_ATTEMPTS for "
                f"{block}.{top_level}:\n{error}\n\n"
                f"Tell the user we couldn't auto-configure this and ask for guidance, "
                f"OR call set_phase to advance and fix in Review phase."
            )
        self._validation_attempts[key] = attempt
        return f"VALIDATION_ERROR (attempt {attempt}/{self._MAX_VALIDATION_ATTEMPTS}):\n{error}"

    # Success — reset attempt counter for this section
    self._validation_attempts.pop(key, None)
    return "OK"


def reset_validation_attempts(self) -> None:
    """Called by ConversationEngine at the start of each new user turn."""
    self._validation_attempts.clear()
```

`ConversationEngine.chat()` calls `self.accumulator.reset_validation_attempts()` immediately after appending the new user message to history.

## 9. Testing Strategy

| Test type | What it covers | Where |
|---|---|---|
| **Schema unit tests** | Each section schema accepts valid configs, rejects each constraint violation, fires each cross-field validator | `dev-kit/tests/schemas/test_<block>_domain.py`, `test_<block>_dpg.py` |
| **Validator integration tests** | `validate_domain_section()` returns OK on valid, error string on each known failure mode | `dev-kit/tests/test_schema_validation.py` |
| **Accumulator tests** | `update()` returns OK / VALIDATION_ERROR / VALIDATION_FAILED_AFTER_3_ATTEMPTS at the right times | `dev-kit/tests/test_accumulator_validation.py` |
| **Retry counter tests** | Counter increments per (block,section); resets on new user turn; resets on success; caps at 3 | Same as above |
| **DPG endpoint tests** | `PUT /api/projects/{slug}/deploy/dpg-values/{block}` rejects invalid YAML with 400 + clear message | `dev-kit/tests/test_app_dpg_values.py` |
| **End-to-end conversation tests** | Mock LLM that produces a known-bad value; verify error feedback → correction → success cycle | `dev-kit/tests/integration/test_devkit_validation_loop.py` |
| **Round-trip tests** | Load each existing `dev-kit/configs/<domain>/*.yaml`, validate against domain schemas, expect green | `dev-kit/tests/test_existing_configs_validate.py` |
| **Round-trip DPG tests** | Each `dev-kit/dpg/*.yaml` validates against its DPG schema | `dev-kit/tests/test_dpg_yamls_validate.py` |

The round-trip tests are critical: they prove the new schemas don't break any existing project (kkb, employ-voice-bot, etc.) before rollout.

## 10. Migration & Rollout

Phased to avoid a big-bang switch:

1. **Land schemas without enforcement** — write all 14 schema files, add round-trip tests against existing configs. No behaviour change.
2. **Wire DPG endpoint validation** — opt-in via env flag `DEVKIT_DPG_SCHEMA_STRICT=1`. Test against existing DPG YAMLs.
3. **Wire accumulator validation** — same env flag. Run a few deploys end-to-end with the existing prompts (still showing old YAML templates) to confirm validation only fires on real failures.
4. **Switch phase prompts to schema injection** — replace `load_template_text` with `_schema_source` per phase. Now LLM sees constraints directly.
5. **Make strict-mode default** — flip the env flag default. Old behaviour available via `DEVKIT_DPG_SCHEMA_STRICT=0` for one release.
6. **Remove the env flag and old code** — `validate_partial`, `dev_kit/schema.py`, template-snippet helpers in `phases.py` are deleted.

## 11. Risks & Open Questions

| # | Risk | Mitigation |
|---|---|---|
| 1 | New schema rejects a config a domain currently relies on (false positive) | Round-trip tests in step 1 catch this before rollout. Add escape hatch: per-block schema can be disabled via env var during initial bake-in. |
| 2 | Schema definitions drift from runtime block schemas over time | Add a CI lint that compares devkit `dpg/*.py` against runtime block `schema/config.py` field-by-field. Fail CI if a runtime field exists in one but not the other. |
| 3 | `inspect.getsource` injection adds many tokens to phase prompts | Token measurement shows current YAML templates are ~200-400 tokens each; Pydantic class source is similar. Net change should be minimal. Watch the `input_tokens` in conversation logs; trim if needed. |
| 4 | Cross-field validators with complex referential integrity (e.g., workflow) become heavy | Validators in `AgentWorkflowSection` are fast (set lookups); benchmarked at <1ms for 20-subagent workflows. |
| 5 | Operator edits a DPG field in a way the schema rejects but the runtime would accept | The DPG schema is authored from the runtime block schema, so this should be rare. If found, fix the DPG schema (looser) — runtime is the source of truth. |
| 6 | LLM still generates invalid configs after schema injection | Layer 2 (tool handler validation + retries) catches it. After 3 attempts, falls back to user. |
